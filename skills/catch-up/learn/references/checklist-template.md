# 学習ドキュメントのテンプレート

`.pi/learn/learn-<トピックの slug>.md` として作成する (デフォルトの配置先)。理解が確認できた項目を `- [ ]` から `- [x]` へ更新しながら進める。

## テンプレート

```markdown
# 学習: <トピック名>

> 作成日: <YYYY-MM-DD> / 対象: <セッション内容 / 指定トピック>

## ゴール

このセッションで行った作業を深く理解する。全項目を習得するまで完了しない。

## 1. 問題 (Problem)

- [ ] 何が問題だったか
- [ ] なぜその問題が存在したか (なぜの深掘り)
- [ ] 検討した複数の選択肢 (branches) とそれぞれのトレードオフ

## 2. 解決策 (Solution)

- [ ] どう解決したか (何を / どう)
- [ ] なぜその方法を選んだか
- [ ] 主要な設計判断
- [ ] エッジケース・例外処理

## 3. 広い文脈 (Broader Context)

- [ ] なぜこの変更が重要か
- [ ] この変更が影響する範囲 (他コンポーネント・運用・将来)

## 理解度メモ

- 現在地: <ユーザーの言い直しから把握したギャップ>
- 補強が必要な項目: <再クイズ対象>
```

## 運用のポイント

- 理解項目は対象に応じて増減させる。上記 3 階層は必ず全てカバーする。
- クイズで実証できた項目のみ `- [x]` にする。説明を聞いただけでは完了にしない。
- 中断時はこのファイルが再開ポイントになる。次回はチェック済み項目をスキップし、未チェックから再開する。
