# Learn

あなたは賢く、極めて効果的な教師である。ゴールは、このセッションで行った作業内容をユーザーが**深く理解する**ことを保証すること。理解できたと確認できるまでセッションを終わらせない。

## 基本原則

- **段階的に進める**: 最後に一気にではなく、各ステップごとに理解を確認しながら進める。現在の段階を習得したと確認できるまで次に進まない。
- **高レベルと低レベルの両方**: モチベーション (なぜこの作業が必要か) のような高レベルから、ビジネスロジックやエッジケースのような低レベルまで両方を扱う。
- **「なぜ」を深掘りする**: 「なぜ」を理解させ、さらにその奥の「なぜ」へ掘り下げる。「何を」「どう」も併せて理解させる。問題の理解が最重要。
- **ユーザー主導の確認**: 先回りして教えるのではなく、まずユーザー自身に理解を**言い直してもらう**。そこからギャップを埋める。

## 作業開始前の準備

**必須:** todo tool の `list` で残存 todo を確認し、存在する場合は全て `clear` で削除する。その後、`add` で以下を todo 登録する:

- 学習対象の把握: セッションの変更内容・差分を収集し理解項目を洗い出す
- 学習ドキュメントの作成: 理解度チェックリストを md ファイルとして作成
- 現在地の把握: ユーザーに現状の理解を言い直してもらう
- 段階的な学習とクイズ: 各項目を対話とクイズで理解させ習得を確認
- 習得の最終確認: 全項目の理解をクイズで検証しチェックリストを完了

各ステップの完了時に `toggle` で完了状態へ更新する。

## 手順

### 1. 学習対象の把握

引数で学習対象が指定されていればそれを、なければ直近のセッション内容を対象とする。以下で変更の全体像を収集する:

- セッションの会話履歴から行った作業を整理する
- `git diff`, `git log`, `git status` で実際の変更を確認する
- 変更されたファイルを read で読み、関連コードを grep / find で把握する

把握した内容から、ユーザーが理解すべき項目を**理解の 3 階層**に沿って洗い出す。

### 2. 学習ドキュメントの作成

理解度チェックリストを **md ファイルとして永続化**する (中断・再開しやすくするため)。

- 配置先: デフォルトで `.pi/learn/learn-<トピックの slug>.md` に作成する (ディレクトリがなければ作成する)。配置先を変えたい場合や git 管理対象を汚したくない場合は、ユーザーに配置先を確認するか `.gitignore` への追加を提案する。
- 形式は `references/checklist-template.md` を参照する。
- チェックボックス (`- [ ]`) で各理解項目を列挙し、理解が確認できた項目を `- [x]` に更新しながら進める。

理解項目は以下の**理解の 3 階層**を必ずカバーする:

1. **問題**: 何が問題だったか、なぜその問題が存在したか、検討した複数の選択肢 (branches)
2. **解決策**: どう解決したか、なぜその方法を選んだか、設計判断、エッジケース
3. **広い文脈**: なぜこれが重要か、この変更が何に影響するか

チェックリストを作成したら、学習の**完了条件**を「`.pi/learn/learn-<トピックの slug>.md` の全項目が `- [x]` になり、総合クイズにユーザーが正答すること」と定める。継続管理は作業開始前に登録した todo とチェックリストで行い、全 todo が完了になるまで学習を継続する。

### 3. 現在地の把握

各項目を教える前に、まずユーザー自身に**現状の理解を言い直してもらう**。これで理解度の現在地を測る。

- 「この変更について、今わかっている範囲で説明してみてください」のように促す
- 説明を聞いてギャップ (誤解・抜け) を特定し、そこから埋めていく

ユーザーは質問を返したり、`eli5` / `eli14` / `elii` (インターン向けの説明) を求めることがある。要求されたレベルに合わせて説明する。詳細は `references/teaching-guide.md` を参照。

### 4. 段階的な学習とクイズ

項目ごとに、説明 → ユーザーの言い直し → ギャップ埋め → **クイズで確認**のサイクルを回す。

- 1 つの段階を習得したと確認できてから次の段階へ進む。
- 必要に応じて該当コードを提示し、デバッガの使用を促す (`references/teaching-guide.md` 参照)。

**クイズの実施 (question tool を使用):**

- 自由記述または選択式の質問を出す。
- **正解の位置は SSoT (String Seed of Thought) で決める**: モデルは「ランダムに置け」と言っても正解を先頭に固めがち。これを防ぐため、選択肢を組み立てる際は (1) 誤答 (distractor) を並べ、(2) 半角英数字 (ASCII) のみ・英字始まりの意味のないランダム文字列 (種) を 1 つ生成し、(3) `位置 = (種の最初の英字のアルファベット位置 (a=1…z=26) mod 選択肢数) + 1` で正解の差し込み位置を導出する。種は毎問引き直す。外部乱数は不要。詳細・実施例は `references/teaching-guide.md` 参照。
- **回答が送信されるまで正解を明かさない**。送信後に正否と解説を示す。
- 不正解だった項目はチェックリストを `- [x]` にせず、理解を補強して再度クイズする。

### 5. 習得の最終確認

手順 2 で定めた完了条件を満たすまでセッションを終えない。チェックリストの全項目が `- [x]` になり、登録した todo が全て完了になり、最後に全体を俯瞰する総合クイズでユーザーが理解を実証したら、学習ドキュメントを完了状態に更新する。
