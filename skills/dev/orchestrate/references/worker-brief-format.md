# Worker タスクブリーフのフォーマット

worker はメインセッションの会話を見られないため、ブリーフは自己完結させる。以下のテンプレートに従って `subagent` の `prompt` を構成する。

## テンプレート

```markdown
## ゴール

<このサブタスクで達成すること。1〜3 文>

## コンテキスト

<worker が知らない前提情報>

- 全体のゴール: <orchestrator が遂行中の大きなゴール (worker の判断基準になる)>
- 関連する事実: <これまでのウェーブで判明した事実、関連ファイルのパス等>
- 検証済みの事実: <orchestrator が裏取り済みで worker が疑わなくてよい事実 (なければ省略)。レビュー・調査系タスクでは特に重要で、これがないと worker は知らない事実を「誤り」として指摘する>

## スコープ

- 対象: <触ってよいファイル・ディレクトリ>
- 対象外: <触ってはいけない範囲、やらないこと>

## 完了条件

- <検証可能な条件。自動検証 (テスト、Lint、ビルド) を優先>

## 制約

- <技術的制約、プロジェクト規約 (例: パッケージマネージャーは bun、コミットは行わない)>

## 報告

完了したら以下のフォーマットで報告すること:

- 結果 (成功 / 部分成功 / 失敗)
- 成果 (要点のみに蒸留。ファイル全文やログ全文は含めない)
- 変更ファイル (path と変更概要)
- 検証 (実行した検証と結果)
- 未解決・引き継ぎ事項
```

`worker` を使う場合、報告フォーマットは worker の system prompt に組み込み済みのため「報告」セクションは省略してよい。`general-purpose` へのフォールバック時は必ず含める。

## 記入例 (調査系)

```markdown
## ゴール

src/auth/ 配下のトークン検証ロジックを調査し、処理フローと外部依存を要約する。

## コンテキスト

- 全体のゴール: 認証ミドルウェアのリファクタリング計画の策定
- 関連する事実: エントリポイントは src/auth/middleware.ts と推定される

## スコープ

- 対象: src/auth/ 配下の読み込みのみ
- 対象外: ファイルの変更は行わない

## 完了条件

- トークン検証の処理フロー (関数呼び出しの連鎖) が要約されている
- 外部依存 (ライブラリ、環境変数、外部 API) が列挙されている

## 制約

- 報告は 500 語以内に蒸留する
```

## 記入例 (実装系)

```markdown
## ゴール

utils/date.ts に ISO 8601 文字列をパースする parseIso() を追加し、テストを書く。

## コンテキスト

- 全体のゴール: 日付処理のライブラリ依存 (moment) の削除
- 関連する事実: 既存テストは `utils/__tests__/date.test.ts` にあり、bun:test を使用

## スコープ

- 対象: `utils/date.ts`, `utils/__tests__/date.test.ts`
- 対象外: moment を使う既存コードの置き換え (別タスクで実施)

## 完了条件

- bun test utils が全件パスする
- 不正な入力で null を返すケースがテストされている

## 制約

- 新しい外部ライブラリを追加しない
- コミットは行わない
```

## ブリーフ設計のチェックリスト

- [ ] worker が追加の質問なしで着手できる情報が揃っているか
- [ ] 完了条件が検証可能か (worker が自己判定できるか)
- [ ] 他の worker と同一ファイルを変更しないか (競合回避)
- [ ] 再投入時: 前回の失敗内容と回避策を「コンテキスト」に追記したか
- [ ] レビュー・調査系: orchestrator が検証済みの事実を明示したか (worker の誤検知防止)
